# opencode-permission-gate

[English](README_eng.md) | 日本語

OpenCode V2 の権限確認を LLM で支援するプラグインです。 \
OpenCode がユーザー確認を求めた操作（`ask`）をレビューします。 \
レビュー結果は、自動承認（`allow`）、確認の継続（`ask`）、拒否（`deny`）のいずれかです。

**既定では `off`（無効）です。** 導入しただけではレビューしません。 \
まず `dry-run` で、権限判定を変えずに提案結果を確認してください。 \
結果を確認してから、自動判定する `auto` に切り替えてください。

## 主な機能

- **`ask` 判定のみをレビュー**: 明示的な `deny`（拒否）設定は変更しません。
- **セッションモデルの自動利用**: 既定では、現在作業中のセッションと同じモデルでレビューします。
- **3つの動作モード**: `off`（無効）、`dry-run`（判定を変えずにレビュー）、`auto`（自動判定）を切り替えられます。
- **柔軟な設定**: 既定の動作モード、危険な操作の扱い、レビュー理由の出力言語などを設定ファイルで指定できます。
- **安全制御**: 危険と判断した操作をブロックするか、ユーザー確認に回すかを選択できます。
- **拒否理由の特定**: OpenCode の設定ルールで拒否されたとき、拒否されたコマンド部分と一致したルールをツールエラーに追記します。
- **監査ログの出力**: レビュー対象の判定結果を、1 行ずつの JSON 形式で記録します。
- **TUI コマンド対応**: ターミナル操作中にモード切り替えや状態確認ができます。

## 動作要件

- V2 プラグイン API に対応した OpenCode V2
- 短い JSON 出力に対応したチャットモデル

## インストール

### GitHub から追加する場合

次のコマンドでプラグインを追加します。

```sh
opencode plugin add github:fateshelled/opencode-permission-gate
```

設定ファイル（`opencode.jsonc`）には、プラグイン名が文字列として追加されます。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["github:fateshelled/opencode-permission-gate"]
}
```

オプションを指定する場合は、次のようにオブジェクト形式へ書き換えます。 \
この例は `auto` を指定しています。まず試す場合は、`dry-run` を指定してください。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "github:fateshelled/opencode-permission-gate",
      "options": {
        "mode": "auto",
        "language": "Japanese",
      },
    },
  ],
}
```

### ローカルクローンから追加する場合

リポジトリをローカルにクローンします。 \
設定ファイル（`~/.config/opencode/opencode.jsonc`）に、クローン先のディレクトリを指定します。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "/path/to/opencode-permission-gate",
      "options": {
        "mode": "off",
        "model": "session",
        "on_danger": "deny",
      },
    },
  ],
}
```

パスは設定ファイルからの相対パスでも構いません。

## クイックスタート

インストール後、TUI で次の手順を実行してください。 \
コマンドによるモード指定は、既定では独自の指定がない子孫セッションにも適用されます。

1. **`dry-run` モードにする** \
   現在のセッションで、権限判定を変えずにレビューを有効にします。

   ```text
   /permission-gate-dry-run
   ```

2. **権限確認が必要なコマンドを実行する** \
   通常どおり操作し、ユーザー確認とバナーの提案結果を確認します。元の `ask` は変わりません。

3. **監査ログを確認する** \
   次の既定のログファイルを開き、判定内容を確認します。 \
   出力先の条件は `audit_path` の説明を参照してください。

   ```text
   ~/.local/share/opencode/permission-gate.jsonl
   ```

4. **`auto` モードに切り替える** \
   ログの判定内容に問題がなければ、レビュー結果を操作に反映します。

   ```text
   /permission-gate-auto
   ```

停止するには `/permission-gate-off` を実行します。 \
`auto` を使う前に、「セキュリティに関する注意点」も確認してください。

## 動作モード

| モード    | 動作内容                                                                      |
| :-------- | :---------------------------------------------------------------------------- |
| `off`     | レビューと権限判定の変更を停止します（既定値）。`explain_denials` は引き続き動作します。 |
| `dry-run` | 提案結果をバナーに表示して監査ログに記録します。元の `ask` 判定は変えません。 |
| `auto`    | レビュー結果に基づいて判定を `allow` / `deny` / `ask` に更新します。          |

- 全体（グローバル）のモードは、設定ファイルの `mode` で指定します。
- TUI コマンドで変更したモードは、既定では独自の指定がない子孫セッションにも適用されます。
- `inherit_to_child_sessions: false` を指定すると、TUI コマンドの変更を現在のセッションだけに限定できます。

## 動作の仕組み

プラグインは `ctx.permission.hook("evaluate")` を使って次の流れで動作します。

1. **対象を確認する**: OpenCode の判定が `ask` で、`skip_actions` に含まれない操作だけを扱います。既存の `allow` と `deny` は変えません。
2. **モードを確認する**: `off` ならレビューしません。`dry-run` と `auto` では危険パターン、キャッシュの順に確認し、必要に応じてモデルで判定します。
3. **結果を適用する**: `auto` ではレビュー結果と処理設定に従います。`dry-run` では元の `ask` を維持します。
4. **ログを記録する**: 対象の操作を `dry-run` / `auto` で判定した場合だけ、監査ログに記録します。

### レビューに失敗した場合

レビューに失敗した場合は `on_failure`（既定値: `ask`）を使います。 \
JSON が不正でも、本文の `allow` / `ask` / `deny` から判定を読み取れれば成功として扱います。 \
モデルの呼び出しや出力解析の失敗が 3 回累積すると、モデルレビューを 60 秒間停止します。 \
停止中もキャッシュは使います。キャッシュに結果がなければ、`on_failure` を適用します。 \
正常な判定を取得すると、失敗回数をリセットします。

### 拒否されたコマンドの特定（`explain_denials`）

OpenCode の設定ルールによる `deny` は、`permission` の `evaluate` フックを呼びません。 \
そのため、プラグインはツールの実行後に呼ばれる `tool.hook("execute.after")` で失敗内容を調べます。 \
拒否されたリソースと一致したルールを取得できる場合、次の情報をツールエラーのメッセージに追記します。

- 拒否されたコマンド部分と、一致したルール
- 同じ呼び出しの中で拒否されなかったコマンド部分

パイプや `&&` で連結したコマンドでは、どの部分が拒否されたかをモデルが判別できます。 \
この機能は動作モード（`off` / `dry-run` / `auto`）に関係なく動作し、権限判定は変更しません。 \
追記する文章は英語です。 \
`"explain_denials": false` を指定すると無効になります。 \
OpenCode が拒否リソースの情報を返さない場合は、メッセージを変更しません。

追記されるメッセージの例を次に示します。

```text
Permission denied: shell
Denied resource: "rm -rf /tmp/x" (rule: "shell" "rm *" -> deny)
Not denied in the same call: "cat package.json", "grep foo"
The whole call did not run. Remove or change only the denied part before you retry.
```

### モデルが参照する情報

モデルは、次の情報を参照して判定します。

- 操作の種類（アクション）
- 対象リソース
- エージェント名
- プロジェクトディレクトリ
- メタデータ

### レビュー結果とバナー表示

モデルは、判定理由（`reason`）と注意点（`hint`）を `language` オプションで指定した言語（既定値: `Japanese`）で返します。 \
`language` は、言語コードだけでなく自然言語でも指定できます。 \
指定例は `"Japanese"`、`"English"`、`"日本語"`、`"英語"` です。 \
空白を整理して前後の空白を除き、先頭 40 文字をモデルへの指示に使います。

`auto` で判定が `ask` になった場合、入力欄の上のバナーに理由を表示します。 \
注意点があれば、その内容も表示します。 \
レビュー失敗時も、`on_failure` が `ask` なら失敗した旨を表示します。

`dry-run` のバナーには、次の内容を表示します。

- `dry-run` の表示
- 処理設定を反映した提案結果（`allow` / `ask` / `deny`）
- 理由と、注意点があればその内容

提案結果は実際には適用せず、元の `ask` を維持します。 \
危険パターンに一致した場合や、レビューに失敗した場合も同じです。 \
モデルを使わない危険パターン判定やレビュー失敗の定型文は、`language` にかかわらず英語です。

### 親子セッションのバナーと表示の制限

親セッションの画面でも、子・孫セッションの確認待ち要求をバナーに表示できます。表示対象と見出しは次のとおりです。

**表示対象は、次の手順で選ぶ先頭の要求だけです。**

1. 現在表示中のセッションを確認します。
2. 続いて、OpenCode が返す順に子孫セッションを確認します。
3. 最初に見つかった空でない確認待ちキューの、先頭要求を対象にします。

対象の要求にこのプラグインのメッセージがなければ、バナーは表示しません。 \
後続にレビュー済みの要求があっても、そのバナーは表示しません。

**見出しは、要求が発生したセッションで区別します。**

- 親を持たないルートセッション: `メイン`
- 子孫セッション: `エージェント名 | セッションタイトル`
- 情報を取得できない場合: エージェント ID（不明なら `Agent`）やセッション ID

子セッションを直接開いた場合も、子自身の要求を `メイン` とは表示しません。

承認または拒否で対象の要求がキューから消えると、その要求のバナーも消えます。 \
次の対象要求があれば、その内容に切り替わります。

バナーは OpenCode 本体の確認待ちキューの順序を再現しています。 \
確認画面でユーザーが選択中の要求を直接取得する公開 API は使えません。 \
本体の表示順序が変わった場合や、先頭以外の要求を表示する画面では、一致を保証できません。

### 使用するモデルの決定順序

モデルの選択は、設定オプション `model` の指定内容によって決まります。

1. **`model` に固定モデル（`provider/model`）を指定した場合**:
   - 常にその固定モデルを使用します（セッションモデルは参照しません）。
2. **`model` が未指定、または `"session"` の場合（既定）**:
   - **優先 1**: 現在のセッションで使用中のモデルを使用します。
   - **優先 2**: セッション情報からモデルを取得できない場合は、OpenCode の既定モデルを使用します。
3. **いずれの方法でもモデルを取得できない場合**:
   - レビュー失敗とみなし、`on_failure` の設定（既定値: `ask`）を適用します。

固定モデルでは `variant`（既定値: `low`）を使い、`none` を指定すると省略します。 \
セッションモデルでは、セッションの variant を引き継ぎます。 \
OpenCode の既定モデルへ切り替えた場合は、variant を付けません。 \
variant 付きの呼び出しに失敗した場合は、variant なしで一度だけ再試行します。

セッションのモデル情報は、取得後 60 秒間キャッシュします。 \
大規模モデルを使うと、コストや応答時間が増える場合があります。

## レビュー結果の処理設定

モデルのレビュー結果や例外状況に応じた処理を設定します。 \
TUI コマンドでは、これらの設定値は変わりません。

| オプション   | 対象となる状況                                               | 選択可能な値        | 既定値 |
| :----------- | :----------------------------------------------------------- | :------------------ | :----- |
| `on_danger`  | モデルが危険と判断した場合、または危険パターンに一致した場合 | `ask` または `deny` | `deny` |
| `on_ask`     | モデルがユーザー確認を推奨した場合                           | `ask` または `deny` | `ask`  |
| `on_failure` | レビューの失敗、タイムアウト、不正出力、モデル未検出の場合   | `ask` または `deny` | `ask`  |

- `ask` はユーザー確認ダイアログを表示し、`deny` は操作をブロックします。
- `on_ask` や `on_failure` を `deny` にすると、正当な操作でも確認なしにブロックされます。ユーザー対話ができない完全自動ワーカーでのみ使用してください。

## TUI コマンド一覧

ターミナル（TUI）で次のコマンドを入力します。 \
モードを変更するコマンドは、現在のセッションの指定を変更します。 \
継承は既定で有効なため、独自の指定がない子孫セッションにも反映されます。

| コマンド                   | 説明                                                    |
| :------------------------- | :------------------------------------------------------ |
| `/permission-gate`         | 操作メニューを表示します。                              |
| `/permission-gate-status`  | 現在の動作状態をダイアログで確認します。                |
| `/permission-gate-auto`    | 現在のセッションを `auto` モードにします。              |
| `/permission-gate-dry-run` | 現在のセッションを `dry-run` モードにします。           |
| `/permission-gate-off`     | 現在のセッションを `off` モードにします。               |
| `/permission-gate-toggle`  | `auto` なら `off`、それ以外なら `auto` に切り替えます。 |
| `/permission-gate-reset`   | セッションのモード指定を解除します。                    |

`reset` 後は、継承が有効なら最も近い祖先のモード指定、次に `auto_agents`、全体設定の `mode` の順でモードが決まります。 \
ただし、`status` の表示と `toggle` の切り替え元は、`auto_agents` を参照しません。 \
自分や継承対象の祖先に指定がなければ、全体設定を使います。 \
そのため、実際のレビュー時のモードと異なる場合があります。

他のクライアントからは RPC メソッド `permission-gate.run` を使えます。 \
`text` には `auto`、`dry-run`、`off`、`toggle`、`status`、`reset` を指定します。 \
モードの変更・解除には `sessionID` が必要です。

## 設定オプション一覧

| オプション                  | 既定値                                                                       | 説明                                                                                                                                        |
| :-------------------------- | :--------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------ |
| `mode`                      | `off`                                                                        | 全体の既定動作モード（`off` / `dry-run` / `auto`）。                                                                                        |
| `model`                     | `session`                                                                    | レビューに使用するモデル。`session` で現在のセッションモデルを使用、または `provider/model` 形式で直接指定。                                |
| `variant`                   | `low`                                                                        | モデルを直接指定した場合のバリアント。不要な場合は `none` を指定。                                                                          |
| `timeout_ms`                | `2500`                                                                       | モデルへの 1 回の生成要求を待つ上限時間（ミリ秒）。最小値は `500`。                                                                         |
| `on_danger`                 | `deny`                                                                       | 危険と判断された操作への対応（`ask` / `deny`）。                                                                                            |
| `on_ask`                    | `ask`                                                                        | ユーザー確認推奨と判定された操作への対応（`ask` / `deny`）。                                                                                |
| `on_failure`                | `ask`                                                                        | レビュー失敗時の対応（`ask` / `deny`）。                                                                                                    |
| `explain_denials`           | `true`                                                                       | OpenCode の設定ルールで拒否されたとき、拒否されたコマンド部分と一致したルールをツールエラーに追記します。                                  |
| `language`                  | `Japanese`                                                                   | 判定理由（`reason`）や注意点（`hint`）を出力する言語。特定の書式はなく、英語（`"English"`）や日本語（`"日本語"`）などの自然言語で指定可能。 |
| `cache_ttl_ms`              | `600000`                                                                     | 判定結果を再利用する時間（ミリ秒。既定は 10 分）。最小値は `1000`。                                                                         |
| `audit_path`                | `~/.local/share/opencode/permission-gate.jsonl`（`$XDG_DATA_HOME` 未設定時） | 監査ログの出力先ファイル。設定ファイルで独自に指定する際は、絶対パスを使用してください（`~` は展開されません）。                            |
| `auto_agents`               | `[]`                                                                         | 自分や継承対象の祖先にモード指定がない場合に `auto` にするエージェント名の配列。                                                            |
| `inherit_to_child_sessions` | `true`                                                                       | 祖先セッションの明示的なモード指定を子孫セッションで参照します。`false` で無効にできます。省略時や真偽値以外の値では既定値を使います。      |
| `skip_actions`              | `["question","external_directory","subagent"]`                               | レビュー対象外の操作名。空でない配列は既定値を置き換え、空配列は既定値に戻します。                                                          |
| `force_ask_patterns`        | `[]`                                                                         | 組み込みの危険パターンに追加する正規表現の配列。一致時はモデルを呼ばず `on_danger` を適用します。                                           |

`audit_path` を省略し、`$XDG_DATA_HOME` が設定されている場合は、`$XDG_DATA_HOME/opencode/permission-gate.jsonl` に記録します。

### 危険パターンとレビュー対象外の操作

`force_ask_patterns` は、大文字・小文字を区別しません。不正な正規表現は無視します。 \
名前に `ask` を含みますが、確認を必須にする設定ではありません。 \
`dry-run` では、一致しても元の `ask` を維持します。

危険パターンは、`resources` を改行で連結した文字列と照合します。 \
キャッシュやモデルより先に判定し、一致した場合はモデルを呼ばずに `on_danger` を適用します。 \
追加パターンを空配列にしても、組み込みパターンは無効になりません。

`skip_actions` の既定値にある `subagent` は、サブエージェントの起動操作だけを対象外にします。 \
子セッション内のコマンドまで一括で除外する設定ではありません。 \
子の操作も、その操作名と動作モードに従ってレビューします。

### 判定キャッシュ

判定キャッシュは、プロジェクトディレクトリ、`action`、`resources`、`agent`、`metadata.cwd` の組み合わせで再利用します。 \
`sessionID`、モデル、ファイル内容はキーに含みません。 \
同じキーなら別セッションでも結果を再利用します。 \
ファイルやモデルの変更だけでは、再レビューしません。

### 設定例（全オプション指定）

不要なオプションは省略可能です。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "github:fateshelled/opencode-permission-gate",
      "options": {
        "mode": "off",                                           // "off" | "dry-run" | "auto"
        "model": "session",                                      // "session" | "provider/model"
        "variant": "low",                                        // Fixed model only: model-specific variant (default: "low"); "none" omits it.
        "timeout_ms": 2500,                                      // Milliseconds; minimum: 500.
        "on_danger": "deny",                                     // "ask" | "deny"
        "on_ask": "ask",                                         // "ask" | "deny"
        "on_failure": "ask",                                     // "ask" | "deny"
        "explain_denials": true,                                 // true | false
        "language": "Japanese",                                  // Any language name or code.
        "cache_ttl_ms": 600000,                                  // Milliseconds; minimum: 1000.
        "audit_path": "/absolute/path/to/permission-gate.jsonl", // Absolute path; no "~" expansion.
        "auto_agents": ["worker"],
        "inherit_to_child_sessions": true,                       // true | false
        "skip_actions": ["question", "external_directory", "subagent"],
        "force_ask_patterns": ["\\bterraform\\s+destroy\\b", "\\bkubectl\\s+delete\\b"]
      }
    }
  ]
}
```

ローカルクローン用の設定例は `examples/opencode.jsonc` にあります。

### 特定エージェントの自動判定（`auto_agents`）

`auto_agents` には、`auto` でレビューしたいエージェント名を登録します。 \
自分にも継承対象の祖先にもモード指定がない場合に適用されます。 \
バックグラウンドワーカーやサブエージェントの自動化に使えます。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "github:fateshelled/opencode-permission-gate",
      "options": {
        "mode": "off",
        "auto_agents": ["worker"]
      }
    }
  ]
}
```

動作モードの優先順位は次のとおりです。

1. セッション個別のコマンド指定（`/permission-gate-off` など）
2. 最も近い祖先セッションのコマンド指定（既定で有効。`inherit_to_child_sessions: false` で無効）
3. 現在の操作のエージェント名に一致する `auto_agents` による自動指定
4. 全体設定の `mode`

### 子孫セッションへのモード継承（`inherit_to_child_sessions`）

子・孫セッションは、既定で最も近い祖先の明示的なモード指定を参照します。 \
設定値は `"inherit_to_child_sessions": true` です。

- 親で `/permission-gate-auto` を実行すると、独自の指定がない子孫も `auto` になります。
- 子で指定した `off` や `dry-run` は親より優先され、その子の子孫にも適用されます。
- 親のモード変更や `reset` は、次のモード確認から反映されます。
- モードを子へコピーしないため、子自身の指定は保持されます。
- 継承対象は `auto`、`off`、`dry-run` の明示的な指定です。祖先の `auto_agents` による自動指定は継承しません。

継承を無効にするには、プラグインの `options` に `"inherit_to_child_sessions": false` を指定します。 \
この場合は祖先を参照せず、従来の優先順位を維持します。 \
省略時や真偽値以外の値では、`true` を使います。

親情報を取得できない場合や循環を検出した場合は、祖先の探索を止めます。 \
その後は、現在の操作の `auto_agents`、全体設定の順に判定します。

`auto_agents` が変更するのは、動作モードだけです。 \
指定モデル、`timeout_ms`、`on_danger` などの設定や、明示的な `deny` ルールには影響しません。

## 監査ログの確認

次の条件をすべて満たす操作を記録します。

- 元の判定が `ask`
- 操作名が `skip_actions` に含まれていない
- 動作モードが `dry-run` または `auto`

`off` の操作や、対象外の操作は記録しません。 \
`dry-run` の `effect` は処理設定を反映した提案結果であり、実際に適用した判定ではありません。 \
各行は次のような JSON です。

```json
{"at":"...","mode":"auto","session":"ses_...","agent":"worker","action":"shell","resources":["git status"],"effect":"allow","reason":"read only"}
```

初めて導入する際は `dry-run` モードで運用し、ログを確認して意図どおりの判定が行われているかを検証してください。

## セキュリティに関する注意点

- **スクリプト内部の検査限界**: モデルはコマンド文字列自体をレビューします。実行対象スクリプトの内部ファイルまでは精査せず、間接的なリスクを見落とす可能性があります。
- **シェルスキャナの併用**: OpenCode 本体のシェルスキャナ機能は無効化せず、有効のまま運用してください。
- **LLM の判定だけに依存しない**: 危険パターンや OpenCode の権限ルールを併用してください。プロンプトでは、プロジェクト内の操作だけを許可するよう指示します。ただし、このプラグインがアクセス範囲を強制的に制限するわけではありません。
- **隔離した環境での実行を推奨**: LLM は誤判定する可能性があります。`auto` は、コンテナなどで隔離した実行環境でのみ使うことを推奨します。

**このプラグインはサンドボックスではありません。** \
worktree は作業ファイルを分ける仕組みであり、OS・プロセス・ネットワークを隔離しません。

## 開発とテスト

プラグイン本体は TypeScript で記述されており、OpenCode が直接読み込んで実行します。 \
開発時の型チェックは次のコマンドで実行できます。

```sh
bun install
bun run typecheck
```

テストには `node:test` を使っています。 \
Node.js と npm がある環境では、次のコマンドで実行できます。`tsx` が未導入なら取得します。

```sh
npx --yes tsx --test tests/*.test.ts
```

自動テストでは、次の内容を検証します。

- モードの継承
- `dry-run` の提案結果
- バナーの対象選択と見出し
- 拒否されたコマンドの特定

実際の TUI 描画や、本体の確認画面との一致は、自動テストの対象外です。 \
次の内容は手動で確認してください。

- 親子それぞれの画面で、見出しを確認する。
- 先頭に通常の権限確認がある間は、後続のバナーが出ないことを確認する。
- 先頭の要求を処理すると、次の対象に切り替わることを確認する。
